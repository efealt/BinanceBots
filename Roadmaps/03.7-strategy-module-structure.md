# Phase 3.7 — Strategy Module Structure

Status: COMPLETE

## Objective

Restructure strategy code before Phase 4 so each strategy has its own module instead of expanding one shared `grid.rs` file.

This phase is organizational only. It must not change strategy behavior, backtest results, execution semantics, parameters, or persistence.

## Target structure

```text
src/trading/
  mod.rs
  types.rs
  portfolio.rs
  simulation.rs
  strategies/
    mod.rs
    static_grid.rs
    dynamic_grid.rs
    volatility_grid.rs
    mean_reversion.rs
    breakout.rs
```

The current Phase 3 fixture moves from `src/trading/grid.rs` to:

`src/trading/strategies/static_grid.rs`

The other four files are reserved strategy modules only. They must not contain invented trading rules until those strategies are explicitly designed.

## Rules

- One strategy concept gets its own module/file.
- Complex strategies may later become their own folder/module without changing the shared engine.
- Shared strategy contracts stay in `src/trading/types.rs`.
- Portfolio/accounting stays in `src/trading/portfolio.rs`.
- Simulated execution stays in `src/trading/simulation.rs`.
- Backtest, Paper, and Live must all call the same strategy implementation.
- Do not create `*_backtest.rs`, `*_paper.rs`, or `*_live.rs` copies of a strategy.
- Preserve the current public imports where practical so the restructure does not force unrelated code changes.
