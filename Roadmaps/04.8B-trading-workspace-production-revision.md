# Phase 4.8B — Trading workspace production revision

## Objective

Turn the Trading page from a run-history-oriented Paper screen into a true trading workspace: the selected registered market is live before any Paper run exists, strategy configuration can be previewed on the chart before execution, operational panels show only the current active run, and the page remains compact and fluid across desktop widths.

This phase does **not** enable Live trading, submit Binance account orders, change strategy rules, or delete prior Paper history.

## Rules

- Complete phases strictly in order and stop after each phase for user review.
- Keep Live mode server-side locked exactly as it is now.
- The selected Symbol/Market pair continues to come from the registered SQLite-backed Binance catalog.
- The browser remains a client only. Market feeds, Paper execution, preview calculations, and canonical run state remain backend-owned where correctness depends on them.
- Preview must reuse the same strategy/grid configuration semantics as Paper start. It must never create a trading run, canonical order, fill, position, or audit event.
- Prior Paper runs remain persisted and queryable; they must not be injected into the current operational workspace when no run is active.
- Responsive/fluid layout is mandatory. No viewport-level horizontal scrolling is allowed; intentionally wide audit tables may scroll only inside their bounded table container.
- Do not change strategy behavior, execution assumptions, or chronology while implementing these UI/workspace changes.

## Sequential phases

### Phase 1 — Active-workspace state instead of stale prior-run state

- [x] Change Trading-page initialization so it restores an **active** Paper run when one exists, but does not auto-load the newest terminal/persisted run into the live workspace when no run is active.
- [x] With no active run, clear run-specific operational state: portfolio values, open orders, current-run audit, run-specific overlays, and run-specific runtime context.
- [x] Keep prior Paper runs untouched in SQLite and preserve their canonical history for later inspection/replay; this phase changes presentation, not persistence.
- [x] After Stop, return the operational workspace to the no-active-run state instead of leaving the stopped run displayed as if it were the current bot.
- [x] Add focused frontend/backend checks proving a terminal historical run cannot populate the active workspace on reload.

**Exit:** Reloading Trading with no active Paper run shows no stale portfolio/orders/audit from an older run, while the older run still exists canonically in storage.

**Implemented:** Active selection now accepts only `arming`/`running` summaries; terminal snapshots clear the workspace, Stop clears the workspace after persistence, frontend contract coverage rejects terminal-only selection, and backend coverage proves stopped runs remain queryable and persisted.

### Phase 2 — Always-on live market chart before Paper start

- [x] Reuse the existing authenticated backend Market service for the Trading chart independently of Paper runtime state.
- [x] As soon as a registered Symbol/Market is selected, load the current Binance 1-minute candle window and attach to the live market stream without requiring **Start Paper**.
- [x] Changing Symbol or Market while no run is active reconnects the chart to that selected market immediately.
- [x] When a Paper run starts, lock the selected instrument as today and layer canonical Paper orders/fills over the same live market chart rather than switching the chart from “off” to “on.”
- [x] Keep market streaming independent of browser ownership and avoid creating a second competing backend market implementation.
- [x] Verify reconnect, symbol/market changes, and no-run live-chart behavior.

**Exit:** Opening Trading with no Paper run already shows a moving live Binance chart for the selected registered market.

**Implemented:** Trading now opens its own client connection to the existing authenticated `/api/market/stream` service for the selected registered Symbol/Market. The WebSocket initial Market snapshot supplies the 1-minute candle window, updates keep it live, run overlays clear independently from market candles, and active Paper order/fill overlays are layered over the same continuous chart.

### Phase 3 — Pre-trade “Show on graph” strategy preview

- [ ] Add a **Show on graph** control beside the Paper run controls.
- [ ] Add a backend preview contract that accepts the visible strategy configuration and calculates the initial intended grid using the same strategy/configuration code and previous-completed-candle semantics used by Paper start.
- [ ] Preview returns visual order/grid levels only; it must not create a run ID, persist canonical events, reserve orders, alter portfolio state, or simulate fills.
- [ ] Draw preview levels on the already-live chart with unmistakable **Preview / not active** styling.
- [ ] After a preview exists, any change to Symbol, Market, replay interval, anchor, fixed anchor price, spacing, levels, quantity, or any other strategy-defining input must immediately mark that preview **stale**.
- [ ] A stale preview may remain visible for comparison, but it must be visually unmistakable that it no longer represents the current controls. The preview action must switch to a warning-style state such as yellow **Update preview** until recalculated.
- [ ] Do not silently leave stale levels looking current. Prefer this explicit stale → **Update preview** workflow over automatic live recalculation; automatic recalculation may be used later only if it proves clearly superior and preserves the same unmistakable freshness state.
- [ ] Pressing **Update preview** recalculates from the current controls and returns the preview to a current/clean state.
- [ ] Starting Paper must use the current visible configuration. If a stale preview exists, the UI must not imply that the old preview is what will execute.
- [ ] Starting Paper replaces preview levels with canonical run order lifetimes/fills.
- [ ] Add parity coverage proving the previewed initial grid matches the initial grid created by Paper for the same configuration and market boundary.
- [ ] Add UI-state coverage proving an input change after preview marks it stale and that a stale preview cannot be mistaken for the current configuration.

**Exit:** The user can configure the strategy, inspect the exact intended grid on the live chart, change parameters without ambiguity, refresh a stale preview via **Update preview**, and then choose whether to start Paper.

### Phase 4 — Compact trading-platform layout

- [ ] Move **Runtime context** (Symbol, Market, replay interval, strategy) out of the bottom of the page and into a new compact top card beside **Runtime health**.
- [ ] Keep the top area fluid: heading, Runtime health, Runtime context, and Execution mode must reflow cleanly as the viewport narrows.
- [ ] Redesign **Position and account state** as one compact wide row on large desktop displays instead of two rows of oversized metric cards.
- [ ] Let portfolio metrics wrap progressively at narrower widths without forcing page-level horizontal scroll.
- [ ] Remove the old bottom Runtime context panel after the top compact version is authoritative.
- [ ] Visually verify the Trading page at wide 4K-style desktop width and progressively narrower desktop/tablet widths.

**Exit:** Runtime identity is visible at the top, the portfolio monitor is compact on wide screens, and narrowing the page causes clean reflow rather than fixed-width overflow.

### Phase 5 — Integrated production acceptance

- [ ] Deploy the completed workspace revision to Render.
- [ ] With **no active run**, verify: registered instrument selection works, live chart streams, portfolio/orders/audit are empty, and no old run is presented as current.
- [ ] Configure a grid and press **Show on graph**; verify preview levels are visually correct and no canonical run/events are created.
- [ ] Start Paper from that same configuration; verify preview is replaced by canonical orders, live fills/portfolio/audit update only for the new current run, and the chart remains continuous.
- [ ] Refresh while the run is active and verify the backend-owned run restores correctly.
- [ ] Stop the run and verify the active workspace clears while the complete stopped-run history remains persisted.
- [ ] Verify the page at wide and narrowed desktop widths with no viewport-level horizontal scrolling.
- [ ] Update `Documents/ARCHITECTURE.md` and the parent Phase 4 roadmap to describe the implemented final behavior.

**Exit:** Trading behaves like an operational platform: live market first, preview before execution, current-run state only, persistent historical audit, and a compact responsive workspace.
