# Phase 4.9 — BinanceGrid → BinanceBots project rename

## Objective

Rename the existing BinanceGrid project to **BinanceBots** as one controlled identity migration across the application branding, GitHub repository, Render service, Render public URL, and project documentation without changing trading behavior or losing any persisted market data, Bot configuration, Run history, authentication history, or production database state.

This is a rename of the existing production system, **not** a new deployment, new database, or new trading architecture.

## Target identity

| Surface | Current | Target |
| --- | --- | --- |
| Product / UI name | Binance Grid / BinanceGrid | BinanceBots |
| GitHub repository | `efealt/BinanceGrid` | `efealt/BinanceBots` |
| Render service | `BinanceGrid` | `BinanceBots` |
| Render URL | `https://binancegrid.onrender.com` | `https://binancebots.onrender.com` if Render makes that slug available |
| Browser/private-console branding | Binance Grid Private quant console | BinanceBots Private quant console |

## Rules

- Complete phases strictly in order.
- Rename the **existing** Render service. Do not create a replacement service merely to obtain a new name or URL.
- Preserve the existing Render persistent disk, environment variables, region, build/start configuration, authentication configuration, and production SQLite data.
- Preserve all Bot IDs, Run IDs, market data, backtest history, Live-Paper history, canonical trading events, and database migrations.
- Do not rename database files, schema tables, migration history, API routes, or persisted identifiers solely for branding. Technical persistence names such as `binance_grid.sqlite3` may remain as historical implementation details unless a separate migration is explicitly approved later.
- Do not change strategy rules, execution semantics, risk behavior, Backtest behavior, Live-Paper behavior, or Live-Real-Account locking as part of this roadmap.
- Keep GitHub `main` as the source of truth and keep Render auto-deploy behavior unchanged except for the already-configured documentation Build Filters.
- Do not assume the desired Render subdomain is available. Verify it before treating the URL rename as complete; if Render cannot provide the target URL on the existing service, stop and report the exact limitation rather than creating a new service.
- Update `Documents/ARCHITECTURE.md` in the same implementation phase whenever the operational source-of-truth names or URLs change.
